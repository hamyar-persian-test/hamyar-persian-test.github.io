# Hamyar Persian IT-Service — نسخهٔ استاتیک برای GitHub Pages

نسخهٔ آزمایشی و مستقل، ساخته‌شده از آخرین طرح سایت. فایل‌ها **HTML + CSS + JavaScript ساده** هستند؛ به وردپرس، PHP، پایگاه‌داده، Node.js یا مرحلهٔ ساخت نیاز ندارند. متن هر زبان در HTML همان صفحه است. این بسته تنظیمات یا متن‌هایی را که فقط در پیشخوان سایت آنلاین ذخیره شده‌اند، وارد نمی‌کند و قالب وردپرس را تغییر نمی‌دهد.

## کدام فایل را ویرایش کنم؟

| مسیر | کاربرد |
| --- | --- |
| `index.html` | صفحهٔ اصلی فارسی؛ تیتر اصلی را در بخش `id="top"` و عنصر `<h1>` پیدا کنید. |
| `de/index.html` | صفحهٔ اصلی آلمانی؛ مستقل از متن فارسی. |
| `impressum/index.html` و `datenschutz/index.html` | پیش‌نویس‌های حقوقی فارسی. نسخه‌های آلمانی همین مسیرها زیر `de/` هستند. |
| `assets/design.css` | استایل‌های طرح ارسالی. |
| `assets/static.css` | استایل‌های ویژهٔ نسخهٔ استاتیک. |
| `assets/site.js` | منوی موبایل، حالت روشن/تاریک، پرسش‌های متداول و باز و بسته کردن پنجره‌های نکات. |
| `assets/` | عکس‌ها، لوگو و فونت‌های محلی؛ مسیر نسبی آن‌ها را حفظ کنید. |

## تست روی GitHub Pages

1. ZIP را از حالت فشرده خارج کنید. در GitHub یک مخزن جدا برای آزمایش بسازید (مثلاً `hamyar-static-test`).
2. **محتویات** بسته را در ریشهٔ شاخهٔ `main` قرار دهید؛ خود ZIP یا یک پوشهٔ اضافی را بارگذاری نکنید. `index.html`، پوشه‌های زبان و `assets/` و فایل `.nojekyll` باید کنار هم باشند. `.nojekyll` ممکن است در نمایش معمول فایل‌ها مخفی باشد.
3. به **Settings → Pages** بروید. زیر **Source**، گزینهٔ **Deploy from a branch** را انتخاب کنید. شاخه را `main` و پوشه را `/(root)` بگذارید و **Save** را بزنید. پس از انتشار، آدرس درج‌شده در همین صفحه را باز کنید.
4. در آدرس Pages، تصویرها، تغییر زبان، منوی موبایل و لینک‌های حقوقی را دوباره بررسی کنید. آدرس یک مخزن پروژه معمولاً به شکل `https://USERNAME.github.io/REPOSITORY/` است. مسیرهای این بسته با زیرپوشهٔ مخزن سازگارند.

راهنمای رسمی: [تنظیم منبع انتشار GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## تست روی کامپیوتر خودتان

برای دیدن سریع سایت، `index.html` را از پوشهٔ استخراج‌شده باز کنید. برای آزمایشی شبیه میزبانی وب، اگر پایتون ۳ دارید، در همان پوشه دستور زیر را اجرا کنید و سپس `http://localhost:8000` را در مرورگر باز کنید:

```sh
python -m http.server 8000 --bind 127.0.0.1
```

در برخی سیستم‌ها باید `python3` یا `py -3` را جایگزین `python` کنید. برای آزمایش روی GitHub نیازی به این دستور ندارید.

## نتیجهٔ تست این بسته

**اصلاح نمایش دسکتاپ:** حرکت نوار خلاصهٔ خدمات در هر دو زبان آهسته‌تر است و با دکمهٔ «مکث» متوقف می‌شود. زیرنویس عکس اصلی پایین تصویر قرار دارد و کارت‌ها و نوشته‌های بخش «خیالتان راحت باشد» حرکت خودکار ندارند. نمایش عادی موبایل حفظ شده است. با فعال بودن تنظیم «کاهش حرکت»، فهرست خدمات ثابت نمایش داده می‌شود.

بستهٔ ZIP پس از استخراج در Chromium، هم در ریشهٔ نشانی و هم زیر مسیری مثل `/hamyar-static-test/` بررسی شد. بارگذاری تصاویر و فونت‌ها، تغییر زبان، حالت روشن/تاریک، منوی موبایل، پرسش‌های متداول، پنجره‌های نکات و پیوندهای حقوقی آزمایش شدند. این تست روی پیش‌نمایش انجام شد؛ هنوز روی مخزن یا نشانی واقعی GitHub Pages اجرا نشده است.

## نکات انتشار

- این نسخه برای **تست** است. متن‌های Impressum و Datenschutz هنوز نمونه‌اند. پیش از معرفی به مشتری آن‌ها را با اطلاعات واقعی و شرایط سرویس میزبانی تکمیل و بررسی کنید. صفحه‌های آزمایشی `noindex` دارند؛ این تنظیم سایت را خصوصی نمی‌کند.
- فایل‌هایی مثل `wp-config.php`، خروجی پایگاه‌داده، نسخهٔ پشتیبان، رمز و کلید خصوصی را در مخزن آزمایشی قرار ندهید. سایت GitHub Pages ممکن است به‌صورت عمومی در دسترس باشد.
- صفحه از فرم تماس، آمارگیر و فونت یا تصویر خارجی استفاده نمی‌کند. ایمیل و اینستاگرام، لینک‌های خروجی‌اند؛ حالت نمایش فقط در مرورگر ذخیره می‌شود. خود GitHub Pages ممکن است برای امنیت، IP بازدیدکنندگان را ثبت کند؛ این را در [مستندات GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection) بررسی کنید.
- برای بررسی حقوق استفاده از عکس‌ها و فونت‌ها به `licenses/` مراجعه کنید.
